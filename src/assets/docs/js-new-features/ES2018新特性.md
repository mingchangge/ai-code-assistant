# ES2018（ES9）新特性

ES2018 在 ES2017 的基础上带来了更多实用且强大的新特性，尤其是在对象操作、异步编程和正则表达式方面。

以下是 ES2018 主要新特性的汇总：

## 1. 异步迭代器（Async Iterators）

ES2018 引入了异步迭代器，允许我们使用 `for await...of` 循环来遍历异步数据源，如网络请求或文件读取。

```javascript
async function* asyncGenerator() {
  let i = 0
  while (i < 3) {
    await new Promise(resolve => setTimeout(resolve, 1000))
    yield i++
  }
}
;(async () => {
  for await (const num of asyncGenerator()) {
    console.log(num)
  }
})()
```

## 2. 对象的剩余/展开属性（Object Rest/Spread Properties）

- **展开运算符**：可以方便地将一个对象的自有（own）可枚举属性“展开”并合并到一个新的对象中，常用于对象的浅拷贝和合并。

  ```javascript
  // 合并属性
  const obj = { a: 1, b: 2, c: 3 }
  const obj2 = { e: 4, f: 5 }
  const newObj = { ...obj, ...obj2, d: 4 }
  console.log(newObj) // { a: 1, b: 2, c: 3, d: 4, e: 4, f: 5 }
  // 浅拷贝
  const objCopy = { ...obj }
  console.log(objCopy) // { a: 1, b: 2, c: 3 }
  // 更新属性值
  const updatedObj = { ...obj, b: 5 }
  console.log(updatedObj) // { a: 1, b: 5, c: 3 }
  ```

- **剩余属性**：可以将对象的剩余属性收集到一个新对象中，常用于函数参数的解构赋值。

  ```javascript
  // 剩余属性
  const obj = { a: 1, b: 2, c: 3, d: 4 }
  const { a, b, ...rest } = obj
  console.log(a) // 1
  console.log(b) // 2
  console.log(rest) // { c: 3, d: 4 }
  ```

## 3. 模板字面量修订 (Template Literal Revision)

在 ES2018 之前，JavaScript 引擎会首先尝试解析模板字面量中的字符串内容，检查是否存在有效的转义序列。如果遇到一个**格式不正确**的转义序列，即使这个模板字面量被一个“标签函数 (tag function)”所使用，引擎也会直接抛出一个 `SyntaxError` 语法错误。

一个“格式不正确”的转义序列包括：

- \x 后面没有跟两位十六进制数 (如 \xz)。
- \u 后面没有跟 {...} 或四位十六进制数 (如 \uA)。
- \ 后面跟一个数字，但它不是一个合法的八进制转义 (如 \9)。

这带来一个很大的问题：如果开发者想创建一个标签函数来处理特定领域的语言（比如处理 Windows 文件路径、LaTeX 公式等），而这些语言的语法恰好包含了在 JavaScript 中非法的转义序列，那么这个标签函数根本就没有机会执行，因为程序在编译阶段就因为语法错误而崩溃了。

ES2018 **放宽**了这一限制。规则改为：如果一个模板字面量是**带标签的 (tagged)**，那么其中的字符串将不再受到严格的转义序列语法检查。现在，当遇到非法的转义序列时，它不会抛出错误，而是将该序列在“熟化”（`cooked`）字符串数组中表示为 `undefined`。标签函数可以通过 `.raw` 属性访问未经处理的原始字符串。

1. **cooked (“熟化”)**: 这是传递给标签函数的第一个参数（通常命名为 strings 或 literals）。它是一个尝试解析转-义序列后的字符串数组。如果某个字符串片段包含了非法的转义序列，那么它在这个数组中对应的值会是 **undefined**。
2. **raw (原始的)**: 这是一个附加在 cooked 数组上的属性 (.raw)。它包含了**完全未经处理的、最原始**的字符串片段数组，所有反斜杠都保持原样。

```javascript
function myTag(strings) {
  console.log('strings (cooked):', strings)
  console.log('strings.raw (raw):', strings.raw)

  // 在这里可以自由地处理原始字符串，
  // 即使其中包含非法的转义序列
  console.log('非法转义序列的原始字符串:', strings.raw[0])
}

// 在现代环境中，这行代码将正常执行，不会抛出错误
myTag`\unicode`
myTag`\xG1`
myTag`\88`
```

输出结果：

```
strings (cooked): [undefined, raw: Array(1)]
strings.raw (raw): ['\\unicode']
非法转义序列的原始字符串: \unicode
strings (cooked): [undefined, raw: Array(1)]
strings.raw (raw): ['\\xG1']
非法转义序列的原始字符串: \xG1
strings (cooked): [undefined, raw: Array(1)]
strings.raw (raw): ['\\88']
非法转义序列的原始字符串: \88
```

## 4. Promise.finally()

ES2018 引入了 `Promise.prototype.finally()` 方法，无论 Promise 最终是成功还是失败，`finally()` 中的代码都会被执行。

```javascript
function checkPromiseStatus(promise) {
  return promise((resolve, reject) => {
    Math.random() > 0.5 ? resolve('success') : reject('error')
  })
}
checkPromiseStatus(Promise)
  .then(result => {
    console.log('Resolved with:', result)
  })
  .catch(error => {
    console.log('Rejected with:', error)
  })
  .finally(() => {
    console.log('Promise has settled (either resolved or rejected)')
  })
```

## 5. 正则表达式改进（RegExp）

ES2018 对正则表达式进行了四项重要的功能增强：

### 1. 命名捕获组 (Named Capture Groups)

允许我们为捕获组命名，而不是只能通过数字索引来引用它们。这使得正则表达式更具可读性和可维护性。

- **语法**：使用 (`?<name>...`) 来命名一个捕获组。
- **访问**：通过返回结果的 `.groups` 属性来访问。

```javascript
const regex = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/
const str = '2025-10-24'
const match = regex.exec(str)
console.log(match.groups.year) // '2025'
console.log(match.groups.month) // '10'
console.log(match.groups.day) // '24'
```

### 2. 后行断言 (Lookbehind Assertions)

ES2018 引入了后行断言，允许我们在匹配某个模式之前检查**之前**的内容是否符合某种条件。这在处理需要上下文信息的文本时非常有用。它是对先行断言 (Lookahead) 的补充。它允许我们匹配一个前面有（或没有）特定模式的字符串。

- **肯定后行断言`(?<=...)`**：匹配一个前面有特定模式的字符串。
- **否定后行断言`(?<!...)`**：匹配一个前面没有特定模式的字符串。

```javascript
const regex = /(?<=\$)\d+/
const str = 'Price: $100'
const match = regex.exec(str)
console.log(match[0]) // '100'
```

或

```javascript
const regex = /(?<!\$)\d+/
const str = 'Price: 100 and $200'
const match = regex.exec(str)
console.log(match[0]) // '100'
```

### 3. s(dotAll)标志

使正则表达式中的 `.` 元字符能够匹配包括换行符在内的任意单个字符。在没有 `s` 标志时，`.` 是不能匹配换行符 `\n` 的。

- **语法**：`/.*/s`
- **核心作用**：让`.`元字符能匹配**换行符（`\n`）**，此前`.`无法匹配换行符。

```javascript
const text = 'hello\nworld'
console.log(text.match(/hello.world/)) // null
console.log(text.match(/hello.world/s)) // ['hello\nworld']
```

### 4. Unicode 属性转义

允许我们使用 `\p{...}` 和 `\P{...}` 来匹配具有特定 Unicode 属性的字符。这使得处理多语言文本和特殊字符变得更加容易。

- **语法**：`\p{...}` 匹配具有指定 Unicode 属性的字符。
- **核心作用**：按 Unicode 属性匹配字符（如\p{Number}匹配所有数字、\p{Emoji}匹配表情）

```javascript
const text = 'hello 你好 123 😊'
console.log(text.match(/\p{Number}/gu)) // ['1', '2', '3']
console.log(text.match(/\p{Emoji}/gu)) //  ['1', '2', '3', '😊']
```
