# ES2017（ES8）新特性

ES2017 引入了多个实用的新特性，提升了 JavaScript 的功能和开发效率。以下是一些主要的新特性：

## 1. 异步函数(Async/Await)

ES2017 引入了 `async` 和 `await` 关键字，使得处理异步操作更加简洁和直观。使用 `async` 声明一个函数，该函数会返回一个 Promise；使用 `await` 可以暂停函数的执行，直到 Promise 解决。

```javascript
async function fetchData() {
  return new Promise(resolve => {
    setTimeout(() => {
      resolve('数据获取成功！')
    }, 2000)
  })
}
async function getData() {
  try {
    const data = await fetchData() // 代码会在这里暂停，直到 Promise 解决
    console.log(data)
  } catch (error) {
    console.error(error)
  }
}

getData() // 调用 async 函数
```

## 2. Object.values() 和 Object.entries()

`Object.keys()`、`Object.values()`、`Object.entries()` 方法用于获取对象的键、值、键值对数组。

- `Object.keys()`: 方法用于获取对象的所有键名，返回一个数组。它是在 ES5 (2009年) 中被引入的。`Object.values()` 和 `Object.entries()` 在功能上是对 `Object.keys()` 的补充。

- ES2017 引入了 `Object.values()` 和 `Object.entries()` 方法，分别用于获取对象的所有值和键值对。

```javascript
const obj = { a: 1, b: 2, c: 3 }
console.log(Object.keys(obj)) // ['a', 'b', 'c']
console.log(Object.values(obj)) // [1, 2, 3]
console.log(Object.entries(obj)) // [['a', 1], ['b', 2], ['c', 3]]
```

## 3. Object.getOwnPropertyDescriptors()

ES2017 引入了 `Object.getOwnPropertyDescriptors()` 方法，用于获取对象所有自身属性（非继承属性）的描述符。一个属性的描述符包含了它的 **value**、**writable**、**enumerable**、**configurable** 以及可能的 **get** 和 **set** 方法。

这个方法的主要用途是实现对象的精确浅拷贝，尤其是当对象包含 **getter** 和 **setter** 时，`Object.assign()` 无法正确拷贝它们，而此方法可以。

```javascript
const obj = { a: 1, b: 2 }
console.log(Object.getOwnPropertyDescriptors(obj))
// {
//   a: { value: 1, writable: true, enumerable: true, configurable: true },
//   b: { value: 2, writable: true, enumerable: true, configurable: true }
// }
```

**浅拷贝：**

```javascript
const source = {
  value: 1,
  get doubled() {
    return this.value * 2
  }
}
const copy1 = Object.assign({}, source)
console.log(copy1) // { value: 1, doubled: 2 }
const descriptors = Object.getOwnPropertyDescriptors(source)
console.log(descriptors)
// {
//     value: { value: 1, writable: true, enumerable: true, configurable: true },
//     doubled: { get: [Function: get doubled], set: undefined, enumerable: true, configurable: true }
// }
const copy2 = Object.defineProperties({}, descriptors)
console.log(copy2)
console.log(copy2.doubled) // 2

copy2.value = 3
console.log(copy2.doubled) // 6
```

## 4. 字符串填充 (String Padding)

ES2017 引入了 `padStart()` 和 `padEnd()` 方法，用于在字符串的开头或结尾填充指定的字符，直到字符串达到指定的长度。这在对齐文本（如在控制台中打印表格）时非常方便。

```javascript
const str = 'Hello'
console.log(str.padStart(6, '*')) // '*Hello'
console.log(str.padEnd(7, '!')) // 'Hello!!'
```

## 5. 函数参数列表和调用中的尾随逗号(Trailing Commas in Function Parameters)

ES2017 允许在函数参数列表和调用时使用尾随逗号，而不会抛出 `SyntaxError` 语法错误。这有助于在添加或删除参数时减少差异，使得在版本控制系统中（如 Git），当添加新的参数时，diff 会更加清晰。

## 6. 共享内存和原子操作(Shared Memory and Atomics)

在浏览器中，JavaScript 默认是单线程的。为了不阻塞主线程（UI 线程），我们使用 Web Workers 来执行耗时的计算任务。但在此之前，主线程和 Worker 线程之间的通信方式存在一个性能瓶颈：

**传统通信方式：postMessage()**
主线程和 Worker 线程通过 `postMessage()` 方法传递消息，这种方式会将数据**复制**（通过结构化克隆算法）一份，传递给另一个线程。如果数据量非常大（比如一个巨大的数组、图片数据或 3D 模型数据），这个复制过程会消耗大量时间和内存，导致性能开销较大。

为了提升多线程环境下的数据共享效率，ES2017 引入了共享内存和原子操作，允许多个线程共享内存区域，并提供了一组原子操作来确保对共享内存的安全访问。

**共享内存的解决方案：**

共享内存允许主线程和 Worker 线程同时访问和操作内存中的同一块数据，而不是来回复制它，这极大地提高了多线程之间数据交互的效率。

这个解决方案由两个核心部分组成：

- **SharedArrayBuffer 对象(SAB)**: 表示一个共享的内存区域，多个线程可以同时访问和修改其内容。
  SharedArrayBuffer (SAB) 是一个原始的、固定长度的二进制数据缓冲区，与 ArrayBuffer 非常相似。关键区别在于：
  - ArrayBuffer: 当你通过 `postMessage()` 发送它时，它会被**复制**一份给接收方。
  - SharedArrayBuffer: 当你通过 `postMessage()` 发送它时，它不会被复制，而是发送一个**引用**。主线程和 Worker 线程都将指向**物理内存中的同一个数据块**。

  就像 `ArrayBuffer` 一样，你不能直接操作 `SharedArrayBuffer`。你需要通过一个“视图”（TypedArray，如 Int32Array）来读取和写入数据。

- **Atomics 对象**: 一个全局对象，提供了一组静态方法，用于在 SharedArrayBuffer 上执行原子（**“原子”** 的意思是**不可分割、不会被中断**。当一个线程在对共享内存的某个位置执行原子操作时，其他线程必须等待该操作完成，才能对该位置进行读写。这保证了 读-改-写 过程的完整性。）操作，确保在多线程环境下读写数据不会发生冲突。

```javascript
const sharedBuffer = new SharedArrayBuffer(1024)
const uint8 = new Uint8Array(sharedBuffer)
Atomics.store(uint8, 0, 42)
console.log(Atomics.load(uint8, 0)) // 42
```

### 重要安全提示：跨域隔离（Cross-Origin Isolation）

由于共享内存可能被用于创建高精度的计时器，这会引发 Spectre 等侧信道攻击的安全风险。因此，现代浏览器要求，要使用 `SharedArrayBuffer`，你的网站必须处于**跨域隔离状态**。
这需要你在服务器响应的 HTTP 头中设置两个值：

- **Cross-Origin-Embedder-Policy (COEP)**：设置为 `require-corp`，这表示你的网站只能加载来自**同源**的资源（包括 `SharedArrayBuffer`）。
- **Cross-Origin-Opener-Policy (COOP)**：设置为 `same-origin`，这表示你的网站只能在**同源**的窗口中打开新的标签页或窗口。

如果不设置这两个头，SharedArrayBuffer 对象将不可用，会抛出错误。

### 总结：

- **共享内存** (`SharedArrayBuffer`) 是一种高性能的多线程数据交换机制，避免了传统 postMessage 的数据复制开销，它带来了竞态条件的风险，即多个线程同时修改数据导致不可预料的结果。
- **原子操作** (`Atomics`) 对象提供了一系列原子操作，是解决竞态条件的标准工具，能确保数据操作的完整性和线程间的安全同步。
- 这是一个**高级特性**，主要用于需要极致性能的场景，如 WebAssembly、浏览器游戏引擎、大规模数据处理等。对于常规应用，postMessage 依然是更简单、更安全的选择。

# 补充说明

## 1. 竞态条件(Race Conditions)

竞态条件是并发编程中一种常见的问题，指的是多个线程或进程同时访问和修改共享数据时，由于操作的执行顺序不可预测，可能导致数据不一致或错误的情况。竞态条件通常发生在以下场景：

- 多个线程同时读取和写入同一个变量或数据结构。
- 线程之间缺乏适当的同步机制，导致操作顺序混乱
- 依赖于共享资源的操作没有正确的锁定或保护措施

解决竞态条件的常见方法包括使用锁（Locks）、信号量（Semaphores）、原子操作（Atomic Operations）等同步机制，确保在同一时间只有一个线程能够访问和修改共享数据，从而保证数据的一致性和正确性。

## 2. SharedArrayBuffer

`SharedArrayBuffer` 是 JavaScript 中用于**在多个线程（主线程与 Worker 线程，或多个 Worker 线程之间）共享二进制内存**的对象。它的核心作用是让不同线程直接访问同一块内存区域，避免了数据复制的开销，特别适合需要高频交互或处理大量数据的并发场景。

### 与普通 `ArrayBuffer` 的区别

普通的 `ArrayBuffer` 是“私有”内存：当通过 `postMessage` 传递给 Worker 时，要么被**复制**（小数据），要么被**转移**（通过 Transferable Objects，原线程失去访问权）。

而 `SharedArrayBuffer` 是“共享”内存：传递给 Worker 时不会复制数据，所有线程都能直接读写同一块内存，内存地址在各线程中保持一致。这种特性极大减少了数据传输的性能损耗，但也引入了**竞态条件**的风险（多个线程同时读写可能导致数据不一致）。

### 核心特性

1. **内存共享**：多个线程操作同一块内存，无需复制数据。
2. **固定大小**：创建时需指定大小（字节数），创建后不可修改。
3. **配合 TypedArray 使用**：自身无法直接读写数据，需通过 `TypedArray`（如 `Int32Array`、`Float64Array` 等）包装后操作（类似 `ArrayBuffer`）。
4. **依赖原子操作**：需通过 `Atomics` 对象提供的原子操作保证多线程读写的安全性（避免竞态条件）。

### 使用场景

适用于需要多线程协同处理**大型数据**或**高频交互**的场景，例如：

- 科学计算（多线程并行处理矩阵、数组）；
- 实时数据处理（如视频帧、传感器数据）；
- 游戏引擎（多线程同步更新游戏状态、物理计算）。

### 使用步骤与示例

使用 `SharedArrayBuffer` 需注意**安全限制**和**线程同步**，具体步骤如下：

#### 1. 满足安全限制（关键！）

由于 `SharedArrayBuffer` 可能被用于 Spectre 等侧信道攻击，浏览器对其有严格的安全限制：**必须在“跨域隔离”环境**中使用。

需在服务器响应头中设置：

```http
Cross-Origin-Opener-Policy: same-origin  # 确保页面在独立的浏览上下文，避免与跨域页面共享资源
Cross-Origin-Embedder-Policy: require-corp  # 要求嵌入的资源必须是同源或带 CORS 许可
```

如果不满足这些条件，浏览器会禁用 `SharedArrayBuffer`（访问时可能抛出 `SecurityError`）。

#### 2. 创建 `SharedArrayBuffer` 并共享

以下是一个简单示例：主线程创建共享内存，传递给 Worker，双方通过 `Atomics` 安全读写数据。

**步骤 1：主线程代码（main.js）**

```javascript
// 1. 创建 SharedArrayBuffer（大小为 4 字节，可存储一个 32 位整数）
const sab = new SharedArrayBuffer(4)

// 2. 用 TypedArray 包装，方便读写（这里用 Int32Array）
const int32Array = new Int32Array(sab)
int32Array[0] = 0 // 初始值设为 0

// 3. 创建 Worker 并传递 SharedArrayBuffer
const worker = new Worker('worker.js')
worker.postMessage(sab) // 传递共享内存，无需复制

// 4. 主线程读取 Worker 修改后的值（用 Atomics 确保安全）
worker.onmessage = e => {
  if (e.data === 'done') {
    const result = Atomics.load(int32Array, 0) // 原子读取索引 0 的值
    console.log('最终结果：', result) // 输出 100（Worker 累加后的值）
  }
}
```

**步骤 2：Worker 线程代码（worker.js）**

```javascript
// 1. 接收主线程传递的 SharedArrayBuffer
self.onmessage = e => {
  const sab = e.data
  const int32Array = new Int32Array(sab) // 同样用 TypedArray 包装

  // 2. 循环累加 100 次（用 Atomics 确保每次加 1 是原子操作）
  for (let i = 0; i < 100; i++) {
    Atomics.add(int32Array, 0, 1) // 原子操作：将索引 0 的值加 1
  }

  // 3. 通知主线程完成
  self.postMessage('done')
}
```

**示例说明**：

- 主线程和 Worker 共享同一块 4 字节内存，通过 `Int32Array` 操作其中的整数。
- Worker 中使用 `Atomics.add` 确保“加 1”操作是原子的（不可被其他线程中断），避免了多线程同时修改导致的错误（如果用普通 `int32Array[0]++`，可能因竞态条件得到错误结果）。

### 关键：`Atomics` 对象的作用

`SharedArrayBuffer` 本身不提供同步机制，多线程同时读写会导致竞态条件。`Atomics` 对象提供了一系列**原子操作**，确保对共享内存的读写是“不可分割”的（操作期间不会被其他线程打断），常用方法包括：

- `Atomics.load(arr, index)`：原子读取指定索引的值。
- `Atomics.store(arr, index, value)`：原子写入值到指定索引。
- `Atomics.add(arr, index, value)`：原子累加（返回旧值）。
- `Atomics.compareExchange(arr, index, expected, replacement)`：如果当前值等于 `expected`，则替换为 `replacement`（原子操作）。
- `Atomics.wait/notify`：用于线程间等待/唤醒（类似条件变量）。

### 兼容性与注意事项

- **兼容性**：现代浏览器（Chrome、Firefox、Edge 等）支持，但必须满足跨域隔离条件；Safari 15.4+ 支持。
- **安全风险**：若不通过 `Atomics` 同步，多线程读写可能导致数据错乱，甚至业务逻辑错误。
- **内存管理**：`SharedArrayBuffer` 无法主动释放，需依赖垃圾回收（当所有线程都不再引用时自动回收）。

### 总结

`SharedArrayBuffer` 是 JavaScript 中实现多线程内存共享的核心对象，通过减少数据复制大幅提升并发性能，但需在**跨域隔离环境**中使用，并配合 `Atomics` 保证线程安全。它是高性能并发场景（如科学计算、实时处理）的重要工具。
