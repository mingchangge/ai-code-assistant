# ES2022（ES13）新特性

ES2022（ES13）是 JavaScript 语言发展中对**类系统**、**错误处理**、**数据访问**等方向进行重要增强的版本，新增特性聚焦于**提升代码封装性、简化常见操作**和**增强调试能力**。以下是全部正式特性的详细说明：

## 1. `at()` 方法

为数组(Array)、字符串(String)和所有类型化数组(TypedArray（Int8Array 等）)引入了 `.at()` 方法。它提供了一种统一且直观的方式，通过索引访问元素，并且支持负数索引，从末尾开始计数，-1 即最后一项，越界返回 undefined。

```javascript
const array = [1, 2, 3, 4, 5]
console.log(array.at(2)) // 3
console.log(array.at(-1)) // 5

const str = 'hello'
console.log(str.at(1)) // 'e'
console.log(str.at(-1)) // 'o'
```

## 2. findLast / findLastIndex

为数组(Array)和类型化数组（TypedArray）新增了 `findLast` 和 `findLastIndex` 方法，用于从数组末尾开始查找符合条件的元素。这两个方法与 `find` 和 `findIndex` 方法类似，区别在于从数组末尾开始遍历。满足条件即返回，不改变原数组。

```javascript
const scores = [65, 80, 90, 70, 55]
const lastPassed = scores.findLast(v => v >= 60)
console.log(lastPassed) // 70
console.log(scores.findLastIndex(v => v < 60)) // 4
```

## 3. Object.hasOwn()

`Object.hasOwn()` 方法用于检查对象是否具有指定的属性，与 `Object.prototype.hasOwnProperty()` 方法功能相同。它返回一个布尔值，指示对象是否直接包含该属性（不考虑原型链），避免了`obj.hasOwnProperty`可能被覆盖的风险（如`obj = { hasOwnProperty: () => false }`）；语法更简洁，可读性更高。

```javascript
const obj = { a: 1, hasOwnProperty: 2 }
console.log(Object.hasOwn(obj, 'a')) // true
console.log(Object.hasOwn(obj, 'hasOwnProperty')) // true
console.log(Object.hasOwn(obj, 'toString')) // false
```

## 4. structuredClone()

`structuredClone()` 方法用于深拷贝（递归复制）任意 JavaScript 值，包括对象、数组、函数、日期、正则表达式等。它解决了 `JSON.parse(JSON.stringify(obj))` 方法在处理循环引用、函数、日期等特殊类型时的局限性，提供了更可靠、更安全的深拷贝解决方案。

```javascript
const obj = { a: 1, b: { c: 2 } }
const clonedObj = structuredClone(obj)
console.log(clonedObj) // { a: 1, b: { c: 2 } }
console.log(clonedObj === obj) // false（引用不同）
console.log(clonedObj.b === obj.b) // false（引用不同）
```

## 5. 正则表达式 d 标志（Indices）

当正则表达式添加 `d` 标志时，匹配结果会包含每个捕获组在原始字符串中的开始和结束索引，方便定位匹配内容的位置。

```javascript
const regex = /a(b+)c/d
const match = regex.exec('abc')
console.log(match)
// ['abc', 'b', index: 0, input: 'abc', indices: [[0, 3], [1, 2]] ...]
```

## 6. 类的私有字段、方法

ES2022 进一步完善了类的私有特性，通过 `#` 符号实现真正的私有成员（字段、方法、访问器、静态成员），彻底阻止外部访问，解决了此前 “伪私有”（如`_field`命名约定）的封装漏洞。

- **私有字段**：通过 `#` 前缀定义，只能在类的内部访问，外部无法直接读写。
- **私有方法**：与字段类似，只能在类的内部调用，外部无法直接调用。

  ```javascript
  class Counter {
    #count = 0 // 实例私有字段
    // 私有方法
    #inc() {
      this.#count++
    }
    // 公共方法：增加计数
    tick() {
      this.#inc()
    }
    // 公共方法：获取当前计数
    value() {
      return this.#count
    }
  }
  const counter = new Counter()
  counter.tick()
  console.log(counter.value()) // 1
  ```

- **私有访问器**：通过 `get` 和 `set` 关键字定义，用于控制对私有字段的访问。
  ```javascript
  class Counter1 {
    #count = 0 // 实例私有字段
    // setter：增加计数
    set #inc(val) {
      this.#count = val
    }
    setValue(val) {
      this.#inc += val
    }
    // getter：获取当前计数
    get #inc() {
      return this.#count * 10
    }
    getValue() {
      return this.#inc
    }
  }
  const counter1 = new Counter1()
  counter1.setValue(3)
  console.log(counter1.getValue()) // 30
  ```
- **私有静态成员**：通过 `static` 关键字定义，只能在类的内部访问，外部无法直接调用。

  ```javascript
  class Counter2 {
    #count = 0 // 实例私有字段：每个实例独立的计数值
    static #zero = 0 // 静态私有字段：所有实例共享的初始值
    static #instanceCount = 0 // 静态私有字段：记录创建的实例数量
    static #totalTicks = 0 // 静态私有字段：记录所有实例的总操作次数

    constructor() {
      // 构造函数：创建实例时，增加实例计数
      Counter2.#instanceCount++
      console.log(`实例 ${Counter2.#instanceCount} 被创建`)
    }
    // 私有方法：增加实例计数
    #inc() {
      this.#count += 3
      // 增加总操作次数
      Counter2.#totalTicks++
    }
    // 公共方法：增加实例计数
    tick() {
      this.#inc()
      // 返回当前实例的计数值
      return this.#count
    }
    // 公共方法：获取当前实例的计数值
    value() {
      return this.#count
    }
    // 静态私有方法：重置静态计数器
    static #reset() {
      console.log(`重置前静态计数器：${this.#zero}`)
      this.#zero = 0
      console.log(`重置后静态计数器：${this.#zero}`)
    }
    // 公共方法：重置静态计数器
    static resetZero() {
      this.#reset()
      console.log('静态初始值计数器已重置')
    }
    // 公共方法：设置静态初始值
    // 设置静态初始值
    static setZero(val) {
      this.#zero = val
      console.log(`静态初始值已设置为：${this.#zero}`)
    }
    // 公共方法：获取当前静态初始值
    static getZero() {
      return this.#zero
    }
    // 公共方法：获取当前静态实例计数
    static getInstanceCount() {
      return this.#instanceCount
    }
    // 公共方法：获取当前静态总操作次数
    static getTotalTicks() {
      return this.#totalTicks
    }
  }
  const counterA = new Counter2()
  counterA.tick()
  counterA.tick()
  console.log(counterA.value()) // 6
  const counterB = new Counter2()
  counterB.tick()
  console.log(counterB.value()) // 3
  // 访问静态方法
  console.log(`当前静态初始值：${Counter2.getZero()}`)
  console.log(`当前静态实例计数：${Counter2.getInstanceCount()}`)
  console.log(`当前静态总操作次数：${Counter2.getTotalTicks()}`)
  // 修改静态初始值
  Counter2.setZero(100)
  console.log(`当前静态初始值：${Counter2.getZero()}`)
  // 重置静态计数器
  Counter2.resetZero()
  console.log(`重置后的静态零值: ${Counter2.getZero()}`)
  ```

## 7. 私有字段的存在性检查（Ergonomic Brand Checks for Private Fields）

允许使用 `in` 运算符来安全地检查一个对象是否拥有某个私有字段，它是一种在类内部检查私有字段是否存在于对象实例中的方法。直接在类外部尝试检查私有字段会因为隐私性而被阻止。

```javascript
class Example {
  #count = 0
  static hasCountField(obj) {
    // 使用 'in' 运算符检查 obj 是否有 #count
    return #count in obj
  }
}
class SubExample extends Example {}
const myInstance = new Example()
const subInstance = new SubExample()
console.log(Example.hasCountField(myInstance)) // 输出：true
console.log(Example.hasCountField(subInstance)) // 输出：true
console.log(Example.hasCountField({})) // 输出：false
```

## 8. 类静态初始化块（Static initialization blocks）

类静态初始化块是在类中定义静态初始化代码块，用于执行复杂的静态成员初始化逻辑（如多步骤赋值、条件初始化、错误处理），多个块会按顺序执行。可访问私有静态成员，解决“静态字段只能表达式初始化”的局限。

```javascript
class Database {
  // 静态字段（待初始化）
  static host
  static port
  static #config // 静态私有字段

  // 第一个静态初始化块：加载配置
  static {
    try {
      this.#config = JSON.parse(localStorage.getItem('dbConfig'))
    } catch (err) {
      // 配置加载失败时使用默认值
      this.#config = { host: 'localhost', port: 3306 }
    }
  }

  // 第二个静态初始化块：初始化host和port
  static {
    this.host = this.#config.host
    this.port = this.#config.port
  }
}

console.log(Database.host) // "localhost"
console.log(Database.port) // 3306
```

## 9. 错误 Cause 链（Error Cause Chains）

为 Error 对象添加了一个 cause 属性，允许你链接错误链。当一个错误导致另一个错误时，你可以将原始错误作为 cause 传递给新的错误。这对于调试和理解复杂的错误流程非常有用。

```javascript
function connectToDatabase() {
  try {
    // 模拟一个数据库连接失败
    throw new Error('Connection refused by database server')
  } catch (dbError) {
    // 捕获数据库错误，并抛出一个更高级别的错误
    throw new Error('Failed to initialize application due to database error', {
      cause: dbError
    })
  }
}

try {
  connectToDatabase()
} catch (appError) {
  console.error(appError.message) // Failed to initialize application due to database error
  console.error(appError.cause) // Error: Connection refused by database server
  console.error(appError.cause.message) // Connection refused by database server
}
```

## 10. `Atomics.waitAsync()`

- **核心作用**：异步等待共享内存（`SharedArrayBuffer`）中的某个位置的值发生变化，避免 `Atomics.wait()` 的阻塞行为，适合并发场景（如 Worker 线程间通信）。
- **背景**：`Atomics.wait()`是同步方法，会阻塞当前线程，而`Atomics.waitAsync()`返回 Promise，在值变化或超时后 resolve，不阻塞线程。
- **语法**：`Atomics.waitAsync(typedArray, index, expectedValue[, timeout])`
  返回值：`{ async: true, promise: Promise }`（异步等待）或 `{ async: false, value: ... }`（同步完成，如值不匹配）。
- **示例**：

  ```javascript
  // 主线程与Worker共享的内存（需要跨域隔离）
  const sab = new SharedArrayBuffer(4)
  const i32a = new Int32Array(sab)

  // 主线程：等待索引0的值从0变为1
  Atomics.waitAsync(i32a, 0, 0).promise.then(result =>
    console.log('等待结果:', result)
  ) // 当值变为1时，输出"ok"

  // Worker线程：修改共享内存的值（触发等待结束）
  // worker.js:
  // const i32a = new Int32Array(sab);
  // Atomics.store(i32a, 0, 1);
  // Atomics.notify(i32a, 0, 1);
  ```

- **使用场景**：多线程（Worker）间的低延迟通信、并发控制（如锁机制），避免线程阻塞导致的性能问题。

## 11. 顶层 `await`

**顶级 await (Top-Level Await)**: 允许在 ES 模块的顶层使用 `await` 表达式，而无需将代码包装在 `async` 异步函数中。这使得在模块中进行异步操作（如加载配置文件、初始化数据库连接等）变得更加简单和直观。顶级 await 只能在模块的顶层使用，不能在函数或类中使用。

```javascript
// config.js（模块）
export const config = await fetch('./config.json').then(res => res.json())

// main.js（导入模块）
import { config } from './config.js'
console.log(config) // 输出配置文件内容
```

**使用场景**：

1. 加载配置文件：在应用启动时加载配置文件，确保应用在运行前具有必要的配置信息。
2. 初始化数据库连接：在应用启动时初始化数据库连接，确保应用在运行前能够与数据库建立连接。
3. 加载动态资源：在应用运行时根据需要加载动态资源，如图片、字体等。
   ```javascript
   // 动态选择导入模块
   const utils = await (process.env.NODE_ENV === 'dev'
     ? import('./utils.dev.js')
     : import('./utils.prod.js'))
   ```

**注意事项**：

1. 仅支持 ES 模块（.mjs或package.json中type: module），CommonJS 模块（.cjs）不支持。
2. 顶级 await 只能在模块的顶层使用，不能在函数或类中使用。
3. 顶级 await 会**会阻塞当前模块及依赖它的模块的加载（类似同步代码）**，直到异步操作完成。因此，在使用顶级 await 时，应该确保异步操作是必要的，而不是简单地为了代码的可读性而使用，错误需用 `try/catch` 包裹。
