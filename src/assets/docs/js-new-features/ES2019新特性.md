# ES2019（es10）新特性

## 1. 对象新增方法

### Object.fromEntries()

Object.fromEntries(): 该方法接收一个键值对的列表（例如 Map 或二维数组），并返回一个新的对象。 它是 Object.entries() 的逆操作，方便从结构化数据生成对象。

```javascript
const map = new Map([
  ['a', 1],
  ['b', 2]
])
console.log(Object.fromEntries(map)) // { a: 1, b: 2 }

const arr = [
  ['a', 1],
  ['b', 2]
]
console.log(Object.fromEntries(arr)) // { a: 1, b: 2 }
```

## 2. 数组新增方法

### Array.prototype.flat()

`Array.prototype.flat(depth)` 方法用于创建一个新数组，并按照指定的深度递归地将所有子数组元素连接起来。默认深度为 1，如果想要展开所有层级的嵌套数组，可以使用 Infinity 作为参数。

```javascript
const arr = [1, [2, 3], [4, [5, 6]]]
console.log(arr.flat(2)) // [1, 2, 3, 4, 5, 6]
```

### Array.prototype.flatMap()

`Array.prototype.flatMap()` 方法首先使用映射函数映射每个元素，然后将结果展平到一个新数组中。它相当于先执行 map() 方法，再执行深度为 1 的 flat() 方法，等价于 `map().flat(1)`但比分别调用这两个方法稍微更高效。

```javascript
const arr = [1, [2, 3], [4, [5, 6]]]
console.log(arr.flatMap(item => item)) // [1, 2, 3, 4, [5, 6]]
```

```javascript
const arr = [1, 2, 3]
console.log(arr.flatMap(item => item * 2)) // [2, 4, 6]
// 等价于
console.log(arr.map(item => item * 2)) // [2, 4, 6]
```

## 3. 字符串新增方法

## String.prototype.trimStart()和

`String.prototype.trimStart()` 或 `trimLeft()`: 方法用于移除字符串开头的空格字符。

```javascript
const str = '  hello world  '
console.log(str.trimStart()) // 'hello world  '
console.log(str.trimLeft()) // 'hello world  '
```

### String.prototype.trimEnd()

`String.prototype.trimEnd()` 或 `trimRight()`: 方法用于移除字符串末尾的空格字符。

```javascript
const str = '  hello world  '
console.log(str.trimEnd()) // '  hello world'
console.log(str.trimRight()) // '  hello world'
```

## 4. Symbol 新增属性

**Symbol.prototype.description**: 这是一个只读属性，用于返回 `Symbol` 对象的可选描述字符串，无需通过 `toString()` 解析。

```javascript
const sym = Symbol('description')
console.log(sym.description) // 'description'
```

## 5. 语法改进

### 1. 可选的 catch 绑定

**可选的 catch 绑定 (Optional Catch Binding)**: 在 ES2019 之前，`try...catch` 语句中的 `catch` 子句必须绑定一个异常变量，即使这个变量不会被使用。现在，如果不需要使用异常对象，可以省略 `catch` 的参数。

```javascript
// 之前的写法
try {
  // ...
  console.log('No error occurred1')
} catch (error) {
  console.log('An error occurred')
}
// 新的写法
try {
  // ...
  console.log('No error occurred2')
} catch {
  console.log('An error occurred')
}
```

## 6. 其他改进

### 1. Function.prototype.toString() 改进

现在函数的 `toString()` 方法会返回更精确的源代码表示，包括注释和空格。

```javascript
function foo(a = 1) {
  // 这是一个注释
  console.log(a)
}
console.log(foo.toString())
// 输出：
// function foo(a = 1) {
//     // 这是一个注释
//     console.log(a)
// }
```

### 2. Array.prototype.sort() 稳定性提升

**Array.prototype.sort() 稳定性提升 (Array.prototype.sort() Stability Improvements)**: 在 ES2019 中，`Array.prototype.sort()` 方法的排序算法被改进为稳定排序（Timsort），即相等元素的相对顺序不会改变。这在处理复杂数据结构时非常有用。

```javascript
const arr = [
  { name: 'Alice', age: 20 },
  { name: 'Bob', age: 20 },
  { name: 'Charlie', age: 25 }
]
arr.sort((a, b) => a.age - b.age)
console.log(arr)
// 输出：
// [
//   { name: 'Alice', age: 20 },
//   { name: 'Bob', age: 20 },
//   { name: 'Charlie', age: 25 }
// ]
```

### 3. JSON 超集支持

允许 JSON 中包含未转义的`U+2028`（行分隔符）和`U+2029`（段分隔符），使 JSON 正式成为 ECMAScript 的超集（此前这两个字符在字符串中会报错）。

```json
const obj={
  "name": "Alice",
  "age": 20,
  "address": "123 Main St.\u2028New York, NY 10001"
}
console.log(JSON.parse(JSON.stringify(obj)))
```

### 4. Array.prototype.includes() 对 NaN 的处理修复

`includes()` 现在能正确识别数组中的`NaN`（此前因`NaN !== NaN`导致无法检测）。

```javascript
const arr = [1, 2, NaN, 4, 5]
console.log(arr.includes(NaN)) // true
console.log(arr.indexOf(NaN)) // -1
```

# 补充说明

`includes` 和 `indexOf` 在判断 `NaN` 时存在差异的根本原因。

简单来说，这个差异源于它们底层使用了**不同的相等性比较算法**。

- `indexOf` 使用的是 **严格相等比较（Strict Equality Comparison）**，也就是我们熟知的 `===`。
- `includes` 使用的是 **SameValueZero 算法**。

接下来，我们详细解释这两种算法如何导致了对 `NaN` 判断的不同结果。

### `indexOf` 与严格相等比较 (`===`)

`indexOf` 方法在数组中从前向后查找指定的元素，并返回其第一个匹配项的索引。如果未找到，则返回 `-1`。在其内部，它使用 `===` 运算符来判断当前遍历到的元素是否与目标值“严格相等”。

根据 JavaScript (ECMAScript) 的规范，`NaN` 是一个非常特殊的值，它有一个核心特性：**`NaN` 不等于任何值，包括它自己**。

我们可以通过简单的代码验证这一点：

```javascript
console.log(NaN === NaN) // 输出: false
```

因为 `indexOf` 依赖于 `===`，当它试图在数组中查找 `NaN` 时，内部的每一次比较 `(array[i] === NaN)` 的结果都将是 `false`，即使数组中确实存在 `NaN`。

**示例：**

```javascript
const arr = [1, 2, NaN, 4]

// 内部工作流程 (简化):
// 1 === NaN  -> false
// 2 === NaN  -> false
// NaN === NaN -> false (关键点!)
// 4 === NaN  -> false
console.log(arr.indexOf(NaN)) // 输出: -1
```

因此，`indexOf` 方法永远无法“找到”数组中的 `NaN`。

### `includes` 与 SameValueZero 算法

`includes` 方法被设计出来的一个重要目的就是为了解决 `indexOf` 在判断 `NaN` 时的这个“怪异”行为。它用于判断数组是否包含某个指定的值，根据情况返回 `true` 或 `false`。

为了能够正确处理 `NaN`，`includes` 采用了 **SameValueZero** 的比较算法。这个算法的规则与严格相等比较 (`===`) 非常相似，但有一个关键区别：

**在 SameValueZero 算法中，`NaN` 被认为与 `NaN` 相等。**

**示例：**

```javascript
const arr = [1, 2, NaN, 4]

// 内部工作流程 (简化):
// Is 1 the same value as NaN? -> false
// Is 2 the same value as NaN? -> false
// Is NaN the same value as NaN? -> true (关键点!)
// 找到后停止遍历
console.log(arr.includes(NaN)) // 输出: true
```

由于 `includes` 使用的算法将 `NaN` 视为与自身相等，所以它能够成功地在数组中找到 `NaN`。

### 总结

| 方法           | 底层比较算法         | `NaN` vs `NaN` 的结果 | 示例 `[NaN].method(NaN)` |
| :------------- | :------------------- | :-------------------- | :----------------------- |
| **`indexOf`**  | 严格相等比较 (`===`) | `false`               | `-1`                     |
| **`includes`** | SameValueZero        | `true`                | `true`                   |

**差异的核心原因**：`indexOf` 遵循了 `===` 的规则，即 `NaN` 不等于自身；而 `includes` 为了提供更符合直觉的编程体验，特意采用了能将 `NaN` 与自身画上等号的 SameValueZero 算法，从而弥补了 `indexOf` 在这方面的不足。
