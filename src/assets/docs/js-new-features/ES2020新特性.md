# ES2020(es11)新特性

## 1. BigInt 类型

**BigInt** 是一种新的原始数据类型，它允许我们表示和操作任意大的整数。在此之前，JavaScript 中的数字类型 (Number) 只能安全地表示介于 -(2^53 - 1) 和 2^53 - 1 之间的整数（即 `Number.MIN_SAFE_INTEGER` 和 `Number.MAX_SAFE_INTEGER`）。超过这个范围的整数在计算时可能会失去精度。BigInt 类型通过在数字后面添加 n 来表示，或者通过调用 `BigInt()` 构造函数来创建。

主要特点：

- **任意精度整数**： 可以表示和操作比 Number 类型支持的最大值更大的整数。
- **使用 n 后缀**： 直接在整数后面加上 n 来创建一个 BigInt。
- **BigInt() 构造函数**： 可以将 Number、字符串或其他 BigInt 转换为 BigInt。
- **与 Number 类型不同**： BigInt 和 Number 类型不能直接混合进行数学运算，需要进行类型转换。
- **支持大多数数学运算符**： +、-、\*、/、%、\*\* 等，但不支持位操作符（&、|、^、~、<<、>>、>>>）以及无符号右移（>>>）。

```javascript
// 使用 n 后缀创建 BigInt
const bigInt1 = 123456789012345678901234567890n

// 使用 BigInt() 构造函数创建 BigInt
const bigInt2 = BigInt('987654321098765432109876543210')

console.log(bigInt1) // 123456789012345678901234567890n
console.log(bigInt2) // 987654321098765432109876543210n
```

应用场景：

- 处理大型 ID 或数据库主键。
- 密码学中的大数运算。
- 金融领域需要精确计算大整数的场景。
- 科学计算中需要高精度整数的场景。

## 2. `globalThis`

**globalThis** 提供了一个标准化的方式来访问全局对象，无论你身处何种 JavaScript 环境（浏览器、Node.js、Web Workers等）。在此之前，访问全局对象需要根据环境使用不同的变量名（如 `window`、`self`、`global`）。

```javascript
console.log(globalThis) // [object Window]
```

## 3. 可选链操作符(Optional Chaining Operator)

**可选链操作符 (Optional Chaining Operator)**: `?.` 是一种新的语法，用于安全地访问嵌套对象的属性，而无需检查每个中间属性是否存在。如果中间属性不存在，表达式将返回 `undefined` 而不是抛出错误。

```javascript
const obj = {
  a: {
    b: {
      c: 42
    }
  }
}

console.log(obj?.a?.b?.c) // 42
console.log(obj?.a?.b?.d) // undefined
console.log(obj?.a?.b?.d?.e) // undefined
```

## 4. 空值合并操作符(Nullish Coalescing Operator) `??`

**空值合并操作符 (Nullish Coalescing Operator)**: `??` 是一种新的逻辑运算符，用于在左侧操作数为 `null` 或 `undefined` 时返回右侧操作数。与逻辑或运算符 (`||`) 不同，`??` **只**在左侧操作数为 `null` 或 `undefined` 时才返回右侧操作数，而不会对其他假值（如 `0`、`''`、`false`）进行判断。

```javascript
const foo = null ?? 'default string'
console.log(foo) // 'default string'
const feature = undefined ?? 'ES2020'
console.log(feature) // 'ES2020'
const bar = 0 ?? 42
console.log(bar) // 0
const baz = '' ?? 'fallback'
console.log(baz) // ''
```

## 5. Promise.allSettled()

**Promise.allSettled()**: 是一种新的 Promise 方法，用于等待多个 Promise 都 settled（无论成功还是失败），并返回一个包含所有 Promise 结果的数组。与 **Promise.all() 不同**，Promise.allSettled() 不会短路，即无论有多少个 Promise，它都会等待所有 Promise 都 settled。

```javascript
const promise1 = Promise.resolve(3)
const promise2 = new Promise((resolve, reject) =>
  setTimeout(reject, 100, 'foo')
)
const promise3 = Promise.resolve(42)

Promise.allSettled([promise1, promise2, promise3]).then(results => {
  console.log(results)
})

// 输出：
// [
//   { status: 'fulfilled', value: 3 },
//   { status: 'rejected', reason: 'foo' },
//   { status: 'fulfilled', value: 42 }
// ]
```

## 6. String.prototype.matchAll()

`String.prototype.matchAll()` 方法返回一个迭代器，该迭代器包含正则表达式在字符串中的**所有匹配结果（包括捕获组）**。解决`String.prototype.match()`在全局匹配（`/g`）时丢失捕获组的问题。

```javascript
const str = '2023-10, 2024-11'
const reg = /(\d{4})-(\d{2})/g

// 用match()只能拿到整体匹配，丢失捕获组
console.log(str.match(reg)) // ["2023-10", "2024-11"]

// 用matchAll()拿到所有匹配+捕获组
const matches = str.matchAll(reg)
for (const match of matches) {
  console.log(match)
}
// 输出：
// 第一次：["2023-10", "2023", "10", ...]
// 第二次：["2024-11", "2024", "11", ...]
```

## 7. 动态导入(Dynamic Import)

**动态导入 (Dynamic Import)**: 允许在代码运行时按需加载模块，而不是在编译时静态导入。使用 `import()` 函数返回一个 Promise，当模块加载完成后解析为模块对象,实现 “按需加载”，减少初始加载体积，优化性能。动态导入在大型应用中特别有用，可以实现代码分割和懒加载。

**语法**：`import(modulePath).then(module => { ... })` 或配合 `await` 使用。

```javascript
// 动态导入模块
import('./module.js')
  .then(module => {
    // 模块加载完成后可以使用 module 中的导出
    console.log(module)
  })
  .catch(error => {
    // 处理加载错误
    console.error(error)
  })
```

## 8. 模块命名空间导出(Module Namespace Export)

**模块命名空间导出 (Module Namespace Export)**: 允许将整个模块作为一个命名空间导出，方便在其他模块中引用。使用 `export * as namespace from 'module'` 语法，可以将模块的所有导出绑定到一个命名空间对象上。

1. 假设你有一个 utils.js 文件：

   ```javascript
   // utils.js
   export const add = (a, b) => a + b
   export const subtract = (a, b) => a - b
   export class MyClass {
     /* ... */
   }
   ```

2. 在ES2020前想再一个模块中导出utils.js的所有内容并作为一个命名空间使用，需要：

   ```javascript
   // main.js
   import * as utils from './utils.js'
   export { utils }
   ```

3. 现在，在ES2020及以后的版本中，你可以直接使用 `export * as namespace from 'module'` 语法导出模块命名空间：
   ```javascript
   // main.js
   export * as utils from './utils.js'
   ```
4. 然后在其他模块中可以这样使用：

   ```javascript
   // anotherModule.js
   import { utils } from './main.js'
   console.log(utils.add(1, 2)) // 3
   console.log(utils.subtract(5, 3)) // 2
   const myInstance = new utils.MyClass()
   ```

**注意事项**：

模块命名空间导出（`export \* as ns from 'module'`）的核心逻辑是：**仅聚合目标模块的 “命名导出”（named exports），而不包含其 “默认导出”（default export）**。即使目标模块同时存在命名导出和默认导出，命名空间对象也只会包含命名导出的成员，默认导出需要单独处理。

## 9. 顶级 await (Top-Level Await) 处于 Stage 3 “候选提案” 状态，2022 年提案完成所有评审

**顶级 await (Top-Level Await)**: 允许在 ES 模块的顶层使用 `await` 表达式，而无需将代码包装在 `async` 异步函数中。这使得在模块中进行异步操作（如加载配置文件、初始化数据库连接等）变得更加简单和直观。顶级 await 只能在模块的顶层使用，不能在函数或类中使用。

```javascript
// config.js（模块）
export const config = await fetch('./config.json').then(res => res.json())

// main.js（导入模块）
import { config } from './config.js'
console.log(config) // 输出配置文件内容
```

**使用场景**：

1. 加载配置文件：在应用启动时加载配置文件，确保应用在运行前具有必要的配置信息。
2. 初始化数据库连接：在应用启动时初始化数据库连接，确保应用在运行前能够与数据库建立连接。
3. 加载动态资源：在应用运行时根据需要加载动态资源，如图片、字体等。
   ```javascript
   // 动态选择导入模块
   const utils = await (process.env.NODE_ENV === 'dev'
     ? import('./utils.dev.js')
     : import('./utils.prod.js'))
   ```

**注意事项**：

1. 仅支持 ES 模块（.mjs或package.json中type: module），CommonJS 模块（.cjs）不支持。
2. 顶级 await 只能在模块的顶层使用，不能在函数或类中使用。
3. 顶级 await 会**会阻塞当前模块及依赖它的模块的加载（类似同步代码）**，直到异步操作完成。因此，在使用顶级 await 时，应该确保异步操作是必要的，而不是简单地为了代码的可读性而使用。

## 10. import.meta

**import.meta**: 是一个新的元数据对象，包含了当前模块的元信息。它可以在模块的顶层使用，用于获取模块的 URL、导入的模块列表等信息。import.meta 是一个**只读对象**，不能被修改，属性随运行环境不同而略有差异。

```javascript
console.log(import.meta)
//输出：
//{url: 'http://localhost:5173/src/views/JsNewFeature/js-new-features/es11.js?t=1761535344515', resolve: ƒ}
```

**使用场景**：

1. 获取当前模块的 URL：在模块中需要获取当前模块的 URL 时，可以使用 import.meta.url 来获取。
2. 动态加载模块：在模块中根据需要动态加载其他模块时，可以使用 import() 函数结合 import.meta.url 来实现。
