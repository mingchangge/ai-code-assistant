# ES2024（es15）新特性

ES2024（ECMAScript 2024）是JavaScript语言的年度更新版本，于2024年6月正式发布。该版本聚焦于提升开发效率、完善现有API，并新增了多个实用特性，主要包括以下内容：

## 1. 数组新增方法

### 1. findFrom() 和 findLastFrom()

解决了现有`find()`和`findLast()`只能从数组首尾开始查找的限制，允许从指定索引开始搜索，更灵活地定位元素。

- findFrom(callback, thisArg, fromIndex)：从fromIndex（含）开始正向查找，返回第一个满足条件的元素。
- findLastFrom(callback, thisArg, fromIndex)：从fromIndex（含）开始反向查找，返回第一个满足条件的元素。

```javascript
const arr = [10, 20, 30, 40, 50]

// 从索引2开始正向查找大于25的元素
console.log(arr.findFrom(x => x > 25, undefined, 2)) // 30

// 从索引3开始反向查找小于35的元素
console.log(arr.findLastFrom(x => x < 35, undefined, 3)) // 30
```

**说明**：

- `fromIndex`支持负数（表示从末尾倒数，如-2即倒数第二个元素）。
- 若`fromIndex`超出数组范围，会自动 clamp 到有效索引（如大于数组长度则视为最后一位）。

### 2. Array.fromAsync() 方法用于将异步可迭代对象转换为数组。

`Array.fromAsync()`是`Array.from()`的异步版本，用于将**异步可迭代对象**（如异步迭代器、`AsyncIterable`接口实现者）转换为数组，解决了传统`Array.from()`无法处理异步数据源的问题。
**核心功能**：

- 支持输入：异步可迭代对象（`AsyncIterator`）、同步可迭代对象（`Iterator`）、类数组对象（`ArrayLike`）。
- 返回值：一个`Promise`对象，最终解析为转换后的数组（与`Array.from()`的同步返回不同）。
- 支持异步映射函数：可以在转换过程中使用异步的`mapFn`对元素进行处理。

**从异步可迭代对象创建数组**:

```javascript
// 示例：将异步迭代器转换为数组
const asyncIterable = (async function* () {
  for (let i = 0; i < 5; i++) {
    await new Promise(resolve => setTimeout(resolve, 10 * i))
    yield i
  }
})()

Array.fromAsync(asyncIterable).then(console.log) // [0, 1, 2, 3, 4]
```

**从同步可迭代对象创建数组**:

```javascript
// 示例：将同步迭代器转换为数组
Array.fromAsync(
  new Map([
    [1, 2],
    [3, 4]
  ])
).then(array => console.log(array))
// [[1, 2], [3, 4]]
```

**从产生 promise 的同步可迭代对象创建数组**:

```javascript
Array.fromAsync(
  new Set([Promise.resolve(1), Promise.resolve(2), Promise.resolve(3)])
).then(array => console.log(array))
// [1, 2, 3]
```

**从 promise 的类数组对象创建数组**:

```javascript
Array.fromAsync({
  length: 3,
  0: Promise.resolve(1),
  1: Promise.resolve(2),
  2: Promise.resolve(3)
}).then(array => console.log(array))
// [1, 2, 3]
```

**可选的 `mapFn` (映射函数)**：
可以提供一个可选的映射函数 `mapFn`，对源中的每个元素进行处理，这个 `mapFn` 可以是 `async` **函数**。在处理流程中，`Array.fromAsync()` 会等待 `mapFn` 的结果兑现，然后将兑现后的值放入数组。

- **语法**：

  ```javascript
  Array.fromAsync(iterableOrArrayLike, mapFn, thisArg)
  ```

- **参数**：
  - `iterableOrArrayLike`：异步可迭代对象（如异步迭代器、`AsyncIterable`接口实现者）、可迭代对象或类数组对象。
  - `mapFn`（可选）：异步映射函数，对源中的每个元素进行处理。如果提供，`Array.fromAsync()` 会等待 `mapFn` 的结果兑现，将兑现后的值放入数组。
  - `thisArg`（可选）：执行 `mapFn` 时的 `this` 值。

- **返回值**：
  - 一个`Promise`对象，最终解析为转换后的数组。

- **示例**：

  ```javascript
  // 将 mapFn 与同步可迭代对象一起使用
  function delayedValue(v) {
    return new Promise(resolve => setTimeout(() => resolve(v), 100))
  }

  Array.fromAsync(
    [delayedValue(1), delayedValue(2), delayedValue(3)],
    element => delayedValue(element * 2)
  ).then(array => console.log(array))
  // [2, 4, 6]
  ```

  或

  ```javascript
  // 将 mapFn 与异步可迭代对象一起使用
  Array.fromAsync(
    (async function* () {
      for (let i = 0; i < 3; i++) {
        await new Promise(resolve => setTimeout(resolve, 100))
        yield i
      }
    })(),
    element => delayedValue(element * 2)
  ).then(array => console.log(array))
  // [0, 2, 4]
  ```

**对比 Promise.all() 和 Array.fromAsync()**
| 特性 | Array.fromAsync() | Promise.all() | Array.from() |
| -------- | ---------------------------------------------------------------- | ------------------------------------------------- | ---------------------------------------------------------------------------- |
| 主要用途 | 从异步可迭代对象或包含 Promise 的可迭代对象/类数组对象创建数组。 | 处理Promise 的可迭代对象，等待所有 Promise 完成。 | 从同步可迭代对象或类数组对象创建数组。 |
| 迭代方式 | 惰性迭代（按需获取下一个值）。 | 预先获取所有值。 | 立即迭代。 |
| 等待方式 | 依次等待对象中产生的每个值兑现。 | 并行等待所有 Promise 兑现。 | 仅处理同步值（除非传入的源是 Promise 集合，但它本身不处理 Promise 的等待）。 |
| 返回值 | Promise，兑现为数组。 | Promise，兑现为结果数组。 | 数组。 |

**总结**：

`Array.fromAsync()` 是现代 JavaScript 中一个非常有用的补充，它**弥补了 `Array.from()` 无法直接处理异步数据源的空白**，特别是在处理像流 (Streams) 这样的数据结构时，它提供了一种简洁、顺序化的方式来将异步数据源的内容收集到标准数组中。

## 2. 正则表达式：v 标志（Unicode 属性类增强）

新增`v`标志以增强 Unicode 处理能力，弥补`u`标志在复杂字符匹配上的不足，尤其对 Emoji、多码点字符（如带肤色修饰的 Emoji）支持更精准。

**核心改进**：

- 支持 Unicode 属性类的**交集**（`&&`）、**差集**（`--`）和**并集**（`||`）。
  - **交集**：`[a-z&&[aeiou]]` 匹配所有小写辅音字母（不包括元音）。

  ```javascript
  const consonantRegex = /[a-z&&[aeiou]]/v
  console.log(consonantRegex.test('a')) // true（小写辅音字母）
  console.log(consonantRegex.test('A')) // false（大写辅音字母，非小写）
  ```

- **并集**：`[a-z||[AEIOU]]` 匹配所有小写字母或大写元音字母。

  ```javascript
  const vowelRegex = /[a-z||[AEIOU]]/v
  console.log(vowelRegex.test('a')) // true（小写元音字母）
  console.log(vowelRegex.test('A')) // true（大写元音字母）
  console.log(vowelRegex.test('1')) // false（非字母）
  ```

- **差集**：`[a-z&&[^aeiou]]` 匹配所有小写辅音字母（不包括元音）。
  ```javascript
  const consonantRegex = /[a-z&&[^aeiou]]/v
  console.log(consonantRegex.test('a')) // false（小写元音字母，非辅音）
  console.log(consonantRegex.test('A')) // false（大写辅音字母，非小写）
  console.log(consonantRegex.test('1')) // false（非字母）
  ```
- 正确处理 “扩展 grapheme 簇”（如👨👩👧👦家庭 Emoji 是多码点组合）。

```javascript
// 匹配所有表情符号（排除文字符号）
const emojiRegex = /\p{Emoji}--\p{Emoji_Presentation=Text}/v
console.log(emojiRegex.test('😊')) // true（纯表情）
console.log(emojiRegex.test('#')) // false（文字符号）

// 匹配所有大写字母或数字（交集）
const alphaNumRegex = /[\p{Letter}&&\p{Uppercase}|\p{Number}]/v
console.log(alphaNumRegex.test('A')) // true
console.log(alphaNumRegex.test('3')) // true
console.log(alphaNumRegex.test('b')) // false
```

**说明**：

- `v`标志是`u`标志的超集，完全兼容`u`的功能（如Unicode转义`\u{...}`）。
- 解决了`u`标志无法精确区分“Emoji呈现形式”（如`®`是文字符号，`©️`是表情符号）的问题。

## 3. `Promise.withResolvers()`

简化Promise的创建流程，无需在`new Promise()`构造函数中手动定义`resolve`和`reject`函数，直接返回包含`promise`、`resolve`、`reject`的对象。

**示例**：

```javascript
// 传统写法
const traditionalPromise = new Promise((resolve, reject) => {
  setTimeout(() => resolve('done'), 1000)
})

// ES2024写法
const { promise, resolve, reject } = Promise.withResolvers()
setTimeout(() => resolve('done'), 1000)

// 用法相同
promise.then(console.log) // 1秒后输出'done'
```

**优势**：

- 避免嵌套函数，更易在外部控制Promise状态（如事件回调中）。
- 减少闭包使用，提升代码可读性。

## 4. `ArrayBuffer.prototype.transfer()`

允许**转移**`ArrayBuffer`的所有权，将原缓冲区的内容和容量转移到新对象，同时使原缓冲区失效（不可再访问），适用于高效内存管理（如大文件处理）。

**示例**：

```javascript
const buffer = new ArrayBuffer(1024) // 1KB缓冲区
const view = new Uint8Array(buffer)
view[0] = 42

// 转移缓冲区所有权
const transferred = buffer.transfer()

console.log(transferred.byteLength) // 1024
console.log(new Uint8Array(transferred)[0]) // 42（内容保留）
console.log(buffer.byteLength) // 0（原缓冲区失效）
```

**扩展用法**：转移时可指定新容量（若大于原容量则补0，小于则截断）：

```javascript
const buffer = new ArrayBuffer(4)
new Uint8Array(buffer).set([1, 2, 3, 4])

// 转移并调整容量为6
const resized = buffer.transfer(6)
console.log(new Uint8Array(resized)) // [1,2,3,4,0,0]
```

## 5. `Object.groupBy()` 和 `Map.groupBy()` 扩展

这两个方法在ES2023中初步引入，ES2024进一步明确行为并修复边缘案例，使其更稳定：

- **功能**：根据回调函数返回的键，将数组元素分组为对象（`Object.groupBy`）或Map（`Map.groupBy`）。
- **ES2024改进**：
  - 统一处理`undefined`键（`Object.groupBy`中转为字符串`"undefined"`）。
  - 修复空数组分组结果（返回空对象/Map）。

**示例**：

```javascript
const people = [
  { name: 'Alice', age: 25 },
  { name: 'Bob', age: 30 },
  { name: 'Charlie', age: 25 }
]

// 按年龄分组为对象
const groupedByAge = Object.groupBy(people, p => p.age)
/* {
  "25": [{ name: 'Alice', ... }, { name: 'Charlie', ... }],
  "30": [{ name: 'Bob', ... }]
} */

// 按年龄分组为Map
const mapGrouped = Map.groupBy(people, p => p.age)
console.log(mapGrouped.get(25)) // 包含Alice和Charlie的数组
```

## 6. 字符串方法：`toWellFormed()`

处理字符串中的“无效Unicode码点”（如孤立的代理对`\uD800`），将其替换为`\uFFFD`（替换字符�），确保字符串是“良构的”（well-formed）。

**示例**：

```javascript
// 包含无效Unicode（孤立代理对）
const invalidStr = 'a\uD800b' // \uD800是无效码点
console.log(invalidStr.toWellFormed()) // "a�b"（无效码点被替换）

// 良构字符串不变
const validStr = '😊abc'
console.log(validStr.toWellFormed() === validStr) // true
```

**用途**：避免在处理用户输入或网络数据时因无效Unicode导致的解析错误。

## 7. `Array.prototype.toReversed()` 等方法扩展至 TypedArray

ES2023为普通数组新增了`toReversed()`、`toSorted()`、`toSpliced()`和`with()`等**不可变方法**（返回新数组，不修改原数组）。ES2024将这些方法扩展到**TypedArray**（如`Uint8Array`、`Float64Array`）。

**示例**：

```javascript
const typedArr = new Uint8Array([3, 1, 2])

// 不可变排序（返回新TypedArray）
const sorted = typedArr.toSorted()
console.log(sorted) // Uint8Array [1, 2, 3]
console.log(typedArr) // Uint8Array [3, 1, 2]（原数组不变）

// 不可变替换（返回新数组）
const replaced = typedArr.with(0, 9)
console.log(replaced) // Uint8Array [9, 1, 2]
```

### 总结

ES2024的特性主要围绕**实用性**和**完善性**：

- 数组查找更灵活（`findFrom`/`findLastFrom`）。
- 正则Unicode处理更精准（`v`标志）。
- Promise创建更简洁（`withResolvers`）。
- 内存管理更高效（`ArrayBuffer.transfer`）。
- 字符串和集合操作更健壮（`toWellFormed`、分组方法改进）。

这些特性进一步降低了开发复杂度，同时提升了JavaScript在处理复杂数据（如Unicode、二进制）时的可靠性。

# 补充说明：

## 1. `Array.fromAsync({length: 3,0: Promise.resolve(1),1: Promise.resolve(2),2: Promise.resolve(3)}).then(array => console.log(array))` 比 `Array.fromAsync(new Set([Promise.resolve(1), Promise.resolve(2), Promise.resolve(3)])).then(array => console.log(array))`先执行完的原因？

要理解两段代码的输出顺序差异，需要深入分析 `Array.fromAsync()` 处理不同输入类型（**可迭代对象** vs **类数组对象**）时的内部逻辑差异，核心在于它们处理元素的方式是**串行**还是**并行**。

### 先明确两个前提：

1. 两段代码中的 `Promise.resolve(1/2/3)` 都是**立即 resolved** 的 Promise（同步完成），但 `Array.fromAsync()` 对它们的处理流程不同。
2. `Array.fromAsync()` 的核心逻辑：根据输入类型（可迭代对象/类数组对象），决定如何“收集并解析”元素。

### 第一段代码：处理 `Set`（可迭代对象）

```javascript
Array.fromAsync(
  new Set([Promise.resolve(1), Promise.resolve(2), Promise.resolve(3)])
).then(array => console.log(array))
```

- `Set` 是**可迭代对象**（实现了 `[Symbol.iterator]`），其迭代器会**逐个同步返回元素**（这里是三个 Promise）。
- `Array.fromAsync()` 处理可迭代对象时，遵循**串行解析逻辑**：
  1. 调用迭代器的 `next()` 方法，获取第一个元素（`Promise.resolve(1)`）。
  2. 等待该 Promise 解析（虽然立即完成，但仍有“等待”的流程）。
  3. 解析完成后，再调用 `next()` 获取第二个元素（`Promise.resolve(2)`），重复等待。
  4. 最后处理第三个元素。

  简单说：**必须等前一个元素解析完成，才会处理下一个**，即使所有 Promise 都是立即 resolved，也会有“逐个处理”的顺序开销。

### 第二段代码：处理类数组对象

```javascript
Array.fromAsync({
  length: 3,
  0: Promise.resolve(1),
  1: Promise.resolve(2),
  2: Promise.resolve(3)
}).then(array => console.log(array))
```

- 输入是**类数组对象**（有 `length` 属性和索引键，但不是可迭代对象）。
- `Array.fromAsync()` 处理类数组对象时，遵循**并行解析逻辑**：
  1. 先根据 `length` 确定所有索引（0、1、2）。
  2. 一次性获取所有索引对应的元素（三个 Promise）。
  3. **并行等待所有 Promise 解析**（因为不需要依赖迭代器的顺序获取，可同时处理）。

  简单说：**所有元素的 Promise 会被同时等待**，即使它们是立即 resolved，也会一起完成，没有“逐个等待”的顺序开销。

### 为什么后者先输出？

- 第一段代码因处理可迭代对象，必须**串行等待**每个元素的解析（即使每个步骤都是同步的，也有顺序执行的微小延迟）。
- 第二段代码因处理类数组对象，**并行等待**所有元素的解析（所有 Promise 同时完成，总耗时更短）。

因此，即使所有 Promise 都是立即 resolved，第二段代码的并行处理流程会比第一段的串行流程更快完成，导致后者先输出结果。
