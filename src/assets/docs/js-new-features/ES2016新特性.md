# ES2016（ES7）新特性

ES2016 的两个主要新特性：`Array.prototype.includes()` 方法和指数运算符 `**`。虽然新增的特性不多，但它们为 JavaScript 带来了更简洁和直观的语法，提升了代码的可读性和开发效率。

## 1. Array.prototype.includes()

ES2016 引入了 `Array.prototype.includes()` 方法，用于判断数组是否包含某个指定的值，返回布尔值。

```javascript
const arr = [1, 2, 3, 4, 5]
console.log(arr.includes(3)) // true
console.log(arr.includes(6)) // false
```

该方法还可以接受第二个参数，表示从数组的哪个索引开始搜索：

```javascript
const arr = [1, 2, 3, 4, 5]
console.log(arr.includes(3, 2)) // true
console.log(arr.includes(3, 3)) // false
```

### 处理稀疏数组

`includes()` 方法会正确处理稀疏数组，即数组中包含 `undefined` 或空元素。

**稀疏数组**（包含空位 `empty slots` 的数组）的空位（如 `[1, 2, , 4, 5]` 中间的空位）在 JavaScript 中本质是 “未初始化的槽位”，`includes` 会将其当作 `undefined` 处理（**空位 ≈ 隐性 undefined**），但仅在搜索目标为 显式传入的`undefined` 时才会匹配，不会自动匹配其他值。

1. 空位会被当作 undefined，因此 includes(undefined) 会返回 true

   ```javascript
   const arr = [1, 2, , 4, 5]
   console.log(arr.includes(3)) // false
   console.log(arr.includes(undefined)) // true
   ```

2. 搜索非 `undefined` 的值时，空位不会被匹配
   ```javascript
   const arr = [1, 2, , 4, 5]
   console.log(arr.includes(3)) // false 空位不等于 3
   console.log(arr.includes(null)) // false 空位不等于 null
   console.log(arr.includes(0)) // false 空位不等于 0
   console.log(arr.includes(false)) // false 空位不等于 false
   ```
3. 与显式传入的 `undefined` 对比
   稀疏数组的空位 vs 数组中显式声明的 undefined，在 includes 看来搜索行为一致（都会匹配 undefined）。

   ```javascript
   const arr = [1, 2, , 4, 5]
   const explicitArr = [1, 2, undefined, 4, 5]
   console.log(arr.includes(undefined)) // true
   console.log(explicitArr.includes(undefined)) // true
   ```

4. 空位的索引仍会被遍历
   includes 会遍历数组的所有索引（包括空位所在的索引），不会像 forEach、map 等方法那样跳过空位。
   ```javascript
   const arr = [1, 2, , 4, 5]
   arr.forEach((value, index) => {
     console.log(index, value)
     // 输出:
     // 0 1
     // 1 2
     // 3 4
     // 4 5
   })
   console.log(arr.includes(undefined)) // true
   ```

## 2. 指数运算符（\*\*）

ES2016 引入了指数运算符 `**`，用于表示幂运算。它的功能类似于 `Math.pow()` 方法。

```javascript
console.log(2 ** 3) // 8
console.log(Math.pow(2, 3)) // 8
```

该运算符也支持复合赋值形式 `**=`：

```javascript
let x = 2
x **= 3
console.log(x) // 8
```

指数运算符（`**`）的优先级在 JavaScript 运算符体系中处于**中高位置**，具体规则如下，结合示例理解更清晰：

### 1. **高于二元算术运算符（+、-、\*、/、%）**

`**` 的优先级高于乘法（`*`）、除法（`/`）、加法（`+`）、减法（`-`）等二元运算符，计算时会优先执行。

```javascript
// 先算指数，再算乘法
2 * 3 ** 2 // 2 * (3** 2) = 2 * 9 = 18
// 先算指数，再算加法
5 + 2 ** 3 // 5 + (2** 3) = 5 + 8 = 13
// 先算指数，再算减法
10 - 3 ** 2 // 10 - (3** 2) = 10 - 9 = 1
```

### 2. **低于一元运算符（+、-、! 等）**

在 JavaScript 的运算符优先级表中，一元运算符（如 `-`、`+`、`~`）的优先级是高于指数运算符 `**` 的。

虽然有明确的优先级规则，但不同语言在处理像 `-2 ** 2` 这样的表达式时有不同的行为：

- **一些语言**（如 Python 和 PHP）会优先执行指数运算，所以 `-2 ** 2` 相当于 `-(2 ** 2)`，结果是 `-4`。
- 而其他语言（如 Bash）则优先处理一元运算符，导致 `-2 ** 2` 等同于 `(-2) ** 2`，结果为 `4`。

为了避免这种跨语言的混乱，JavaScript 的设计者干脆规定，当一元运算符（如：`+`、`-`、`!`、`~`、`typeof`、`void`）紧跟在指数运算符的前面时，这是一种语法错误：“未捕获的语法错误：在幂表达式之前立即使用一元运算符。必须使用括号来消除运算符优先级歧义`**`”。

这是 JavaScript 中的一种设计选择，旨在避免此类表达式求值方式的歧义。 例如，在表达式中`-2 ** 2`，我们无法明确其意图是`(-2) ** 2`（求值为 4）还是`-(2 \*\* 2)`（求值为 -4）。

### 3. **结合性：右结合（与其他算术运算符不同）**

大多数算术运算符（如 `+`、`*`）是**左结合**（从左到右计算），但 `**` 是**右结合**（从右到左计算）。

```javascript
// 左结合运算符（如 *）：从左到右
2 * 3 * 4 // (2 * 3) * 4 = 24

// 右结合运算符（**）：从右到左
2 ** (3 ** 2) // 2 **(3** 2) = 2 **9 = 512
// 若想左结合计算，需用括号
;(2 ** 3) ** 2 // 8** 2 = 64
```

### 4. **高于赋值运算符（=、+=、**= 等）\*\*

赋值运算符的优先级极低，`**` 会先计算，再执行赋值。

```javascript
let x
x = 2 ** 3 // 先算 2**3=8，再赋值给x → x=8
x **= 2 // 等价于 x = x **2 → 8**2=64
```

### 优先级总结表（从高到低）

| 运算符类型         | 示例          | 与 `**` 的关系                          |
| ------------------ | ------------- | --------------------------------------- |
| 括号（()）         | `(a + b)** c` | 优先级最高，可强制改变顺序              |
| 一元运算符         | `-a`、`!a`    | 优先级高于 `**`，必须使用括号来消除歧义 |
| 指数运算符（\*\*） | `a** b`       | 自身优先级                              |
| 乘法/除法（\*、/） | `a * b`       | 优先级低于 `**`                         |
| 加法/减法（+、-）  | `a + b`       | 优先级低于 `**`                         |
| 赋值运算符         | `a = b`       | 优先级低于 `**`                         |

### 关键提醒

涉及负号与 `**` 时，务必注意：`-x** y` 等价于 `-(x **y)`，而非 `(-x)** y`（后者需用括号 `(-x)**y` 实现）。这是实际开发中最容易出错的场景。
