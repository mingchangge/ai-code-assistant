# ES2021(es12)新特性

## 1. 逻辑赋值运算符（Logical Assignment Operators）

将逻辑运算符（`||`、`&&`、`??`）与赋值运算结合，简化 “条件判断后赋值” 的代码。

- `||=`：如果左侧操作数为 false，则执行赋值。

  ```js
  let a = 0
  a ||= 10 // a = 10
  ```

- `&&=`：如果左侧操作数为 true，则执行赋值。

  ```js
  let b = 10
  b &&= 20 // b = 20
  ```

- `??=`：如果变量为 `null` 或 `undefined`，则赋值。

  ```js
  let c = null
  c ??= 30 // c = 30
  ```

## 2. 数字分隔符（Numeric Separators）

允许在数字字面量中使用下划线 `_` 作为分隔符，以提高数字的可读性。这只是语法糖，不会影响数字的实际值。但是不能在开头、结尾或小数点前后连续出现。

```js
let d = 1_000_000 // d = 1000000
```

## 3. 字符串 `replaceAll()` 方法

无需正则表达式，直接替换字符串中**所有匹配的子串**，区别于 `replace()` 仅替换第一个匹配，或需加 `/g` 修饰符才能全局替换。

```js
const str = 'a-b-c'
console.log(str.replace(/-/g, '')) // newStr = 'abc'
console.log(str.replaceAll('-', '')) // newStr = 'abc'
```

## 4. Promise.any() 方法

`Promise.any()` 接收一个 Promise 可迭代对象，并返回一个新的 Promise。当可迭代对象中**只要有一个 Promise 成功（`fulfilled`）**，就立即返回该成功结果；**若所有 Promise 都失败（`rejected`）**，则返回一个包含所有失败原因的 `AggregateError`。

**与其他 Promise 方法的区别**

- `Promise.race()`：返回第一个完成（无论成功或失败）的 Promise。
- `Promise.all()`：返回所有 Promise 都成功时的结果数组；若有一个失败，则立即拒绝。
- `Promise.any()`：返回**第一个**成功的 Promise；若所有 Promise 都失败，则返回 `AggregateError`。

```js
Promise.any([
  Promise.reject('error1'),
  Promise.reject('error2'),
  Promise.resolve('success')
])
  .then(result => {
    console.log(result) // 'success'
  })
  .catch(errors => {
    console.log(errors) // AggregateError: All promises were rejected
  })
```

## 5. WeakRefs 类

`WeakRef`（弱引用）和`FinalizationRegistry`（终结器注册表）是ES2021新增的低级内存管理API，它们的设计目标是**在不阻止垃圾回收的前提下，跟踪对象的生命周期**，主要用于解决“强引用导致的不必要内存占用”问题。但由于垃圾回收（GC）的不确定性，它们的使用场景非常有限，且需谨慎使用。

### 核心概念回顾

- **`WeakRef`**：创建对对象的“弱引用”，即这种引用不会阻止垃圾回收器（GC）回收该对象。当对象没有任何强引用时，即使有弱引用，也可能被GC回收。通过`weakRef.deref()`可获取对象（若未被回收则返回对象，否则返回`undefined`）。
- **`FinalizationRegistry`**：注册一个回调函数（终结器），当被弱引用的对象**被GC回收后**，该回调会被触发，可用于清理与对象关联的资源。

### 典型使用场景

#### 1. 自动清理的缓存（最常见场景）

缓存是最适合`WeakRef`和`FinalizationRegistry`的场景。传统缓存（如`Map`）会通过强引用持有缓存值，即使这些值在其他地方已不再使用，也会因缓存的强引用而无法被GC回收，导致内存泄漏。

而通过`WeakRef`存储缓存值，结合`FinalizationRegistry`在值被回收时删除缓存键，可实现“当缓存值不再被外部使用时，自动从缓存中移除”的效果。

**示例：实现自动清理的缓存**

```javascript
// 1. 创建终结器注册表：当缓存值被回收时，删除对应的缓存键
const cacheCleaner = new FinalizationRegistry(key => {
  console.log(`缓存值被回收，清理键: ${key}`)
  cache.delete(key) // 从缓存中删除键
})

// 2. 缓存本体（用Map存储键→弱引用值）
const cache = new Map()

// 3. 往缓存中添加数据
function addToCache(key, value) {
  // 用WeakRef弱引用value（不阻止GC回收value）
  const weakRef = new WeakRef(value)
  cache.set(key, weakRef)

  // 注册终结器：当value被回收时，触发cacheCleaner的回调（传入key用于清理）
  cacheCleaner.register(value, key)
}

// 4. 从缓存中获取数据
function getFromCache(key) {
  const weakRef = cache.get(key)
  if (weakRef) {
    return weakRef.deref() // 若value未被回收，返回它；否则返回undefined
  }
  return undefined
}

// 测试
let obj = { data: '需要缓存的数据' }
addToCache('obj1', obj)

console.log(getFromCache('obj1')) // { data: "需要缓存的数据" }（未被回收）

// 解除对obj的强引用（此时只有缓存中的弱引用）
obj = null

// 手动触发GC（实际环境中不可控，这里仅为演示）
// 浏览器中可在DevTools的Memory面板手动触发，Node.js中可用--expose-gc并调用global.gc()
// 触发后，obj会被回收，cacheCleaner的回调执行，cache中"obj1"被删除
console.log(getFromCache('obj1')) // undefined（已被清理）
```

**优势**：缓存不会“记住”不再被使用的值，避免内存堆积，尤其适合缓存大型对象（如DOM元素、数据集合）。

#### 2. 关联资源的自动释放

当一个对象关联了外部资源（如临时DOM节点、文件句柄、网络连接等），且这些资源需要在对象被回收时释放，`FinalizationRegistry`可用于触发释放逻辑。

**示例：释放与对象关联的临时DOM资源**

```javascript
// 终结器：当对象被回收时，移除关联的临时DOM元素
const domCleaner = new FinalizationRegistry(tempElement => {
  console.log('对象被回收，移除临时DOM元素')
  tempElement.remove() // 释放DOM资源
})

// 创建一个关联临时DOM的对象
function createTempObject() {
  const obj = { name: '临时对象' }
  // 创建临时DOM元素（仅与obj关联）
  const tempDiv = document.createElement('div')
  tempDiv.textContent = '临时内容'
  document.body.appendChild(tempDiv)

  // 注册终结器：当obj被回收时，释放tempDiv
  domCleaner.register(obj, tempDiv)

  return obj
}

// 测试
let tempObj = createTempObject() // 此时tempDiv已添加到页面

// 解除强引用：obj不再被使用
tempObj = null

// 当obj被GC回收后，domCleaner触发，tempDiv被移除
```

**优势**：无需手动调用`cleanup()`方法，资源释放与对象生命周期自动绑定，减少漏释放风险。

#### 3. 临时元数据跟踪

有时需要为对象附加临时元数据（如调试信息、统计数据），但不希望这些元数据阻止对象被回收。`WeakRef`可用于存储元数据与对象的关联，当对象被回收时，元数据也可自动失效。

**示例：跟踪对象的访问次数（临时元数据）**

```javascript
// 存储元数据：键为对象的弱引用，值为访问次数
const metadata = new Map()
// 终结器：当对象被回收时，删除对应的元数据
const metaCleaner = new FinalizationRegistry(weakRef => {
  metadata.delete(weakRef)
})

// 记录对象访问次数
function trackAccess(obj) {
  const weakRef = new WeakRef(obj)
  // 若元数据不存在，初始化并注册终结器
  if (!metadata.has(weakRef)) {
    metadata.set(weakRef, 0)
    metaCleaner.register(obj, weakRef) // 关联obj和weakRef
  }
  // 访问次数+1
  metadata.set(weakRef, metadata.get(weakRef) + 1)
}

// 测试
let testObj = { id: 1 }
trackAccess(testObj) // 访问次数1
trackAccess(testObj) // 访问次数2

console.log(metadata.get(new WeakRef(testObj))) // 2（未被回收）

testObj = null // 解除强引用

// 当testObj被回收后，metadata中对应的条目被删除
```

### 不适合的场景（重要！）

由于GC的触发时机完全由JS引擎决定（不可预测，可能立即触发，也可能延迟很久，甚至在页面关闭前都不触发），以下场景绝对不能使用：

- **关键资源释放**：如数据库连接、文件句柄等必须及时释放的资源（可能因GC延迟导致资源耗尽）。
- **业务逻辑依赖**：如“对象回收后必须执行某个步骤”（如状态更新、日志记录），可能因GC未触发而导致逻辑错误。
- **高频操作**：频繁创建`WeakRef`和`FinalizationRegistry`会增加GC负担，影响性能。

### 总结

`WeakRef`和`FinalizationRegistry`是**辅助性的内存管理工具**，仅适合“非关键、可延迟、与对象生命周期绑定”的场景（如自动清理缓存、临时资源释放）。它们的价值在于“减少手动清理代码”，但不能替代主动的内存管理（如手动解除引用、调用`destroy()`方法）。

实际开发中，优先考虑`WeakMap`和`WeakSet`（它们对键进行弱引用，场景更明确且更安全），仅当需要对“值”进行弱引用时，才考虑`WeakRef`。
