# 前端健康分析 Agent 与 RAG 架构设计 v2.0

## 1. 核心设计理念

我们将传统的“图表展示”升级为 **“智能分析报告”** 💡。系统不再只是画出体重折线，而是像真人教练一样：

- **👁️ 看得懂**：识别数据波动（趋势计算）。
- **📚 有知识**：根据年龄、性别匹配医学标准（RAG 检索）。
- **🗣️ 会说话**：输出“肌肉涨了是好事”这种带有语义温度的建议。

**架构精髓**：

- **Agent（智能体）**：基于 **LangChain LCEL** 构建的流水线引擎，负责调度清洗、计算、RAG、绘图等原子能力。
- **RAG（检索增强）**：采用 **“向量检索 + 规则过滤”** 的混合模式。用结构化的 JSON 知识库替代昂贵的大模型，实现毫秒级响应且 0 幻觉。
- **Config Driven（配置驱动）**：业务逻辑（如“体重应该查趋势还是查数值”）内聚在配置文件中，Agent 核心代码彻底解耦。

## 2. 目录结构与职责分工

模块📂 位于 `src/services/advisor/`，职责界限分明：

```text
src/services/
├── ocr/                     # [OCR Layer] 光学字符识别模块
    ├── rag/
    │   └── embedding-engine.ts  # [Core] 底层 WebGPU 向量化引擎 (共享模块)
└── advisor/
    ├── index.ts                  # [Facade] 统一入口，对外暴露 AdvisorService
    ├── types.ts                  # [Type] 领域模型定义 (MetricConfig, AnalysisResult)
    ├── config/                   # [Config Layer] 业务的大脑
    │   └── metrics.ts            # **核心配置**：定义指标元数据及 RAG 路由策略
    ├── core/                     # [Tools Layer] 纯函数工具箱
    │   ├── data-cleaner.ts       # 数据清洗与标准化
    │   ├── trend-math.ts         # 数学计算 (斜率、趋势判定)
    │   └── chart-factory.ts      # ECharts 配置生成器
    ├── rag/                      # [Knowledge Layer] 知识检索层
    │   ├── langchain-adapter.ts  # [Adapter] 将底层引擎包装为 LangChain Embeddings 接口
    │   ├── vector-store.ts       # [Store] 向量数据库 (混合检索逻辑实现)
    │   └── knowledge-base.ts     # [Data] 标准化知识库 (全区间覆盖)
    └── agent/                    # [Agent Layer] 调度层
        ├── tools.ts              # [Tool] 将 Core 函数封装为 LangChain Tools
        └── health-agent.ts       # [Engine] 基于 LCEL 的并行流水线引擎
```

## 3. 关键模块实现解析 🛠️

### A. 基于 LCEL 的并行流水线 (Agent Pipeline)

在 `health-agent.ts` 中，我们抛弃了传统的手写循环，转而使用 **LangChain Expression Language (LCEL)** 构建了一套类型安全、高度并行的处理链：

1.  **Clean Chain**: 调用 `cleanDataTool` 将原始 JSON 清洗为标准结构。
2.  **Splitter**: 将大数据集拆解为 N 个独立的 `MetricTaskInput`。
3.  **Map Runner**: 利用 `RunnableLambda` + `Promise.all` 实现 **真·并行处理**。Math 计算与 RAG 检索并发执行，极大降低了延迟。
4.  **Micro Chain**: 每个指标的处理逻辑被封装为一个原子链：
    `Math Tool` -> `Metric Config Logic` -> `RAG & Chart Tools` -> `Format`。

> ✨ **亮点**：LCEL 的引入使得数据流清晰可见，且天然支持未来的 Trace 调试与模块替换（如将 RAG 替换为 LLM）。

### B. 混合检索机制 (Hybrid RAG)

在 `vector-store.ts` 中，我们实现了一套 **“向量 + 规则”** 的双重保障机制，解决了纯向量检索“不懂数学”的痛点：

1.  **第一轮：严格匹配 (Strict Mode)**
    - **语义搜索**：计算 Query 向量相似度。
    - **硬规则过滤**：强制要求 `Category`, `Gender` 匹配。
    - **数值过滤**：强制要求当前数值落在知识库定义的 `valueRange` (闭区间) 内。
    - **年龄过滤**：强制要求用户年龄符合 `ageRange`。

2.  **第二轮：兜底匹配 (Fallback Mode)**
    - 如果用户的数值落入知识库的“真空区”（严格模式无结果），系统会自动放宽条件。
    - 仅匹配 `Category` 和 `Gender`，寻找该分类下的通用建议（如“保持健康生活方式”），确保用户永远不会看到空白结果。

> ✨ **价值**：既保留了向量检索的语义理解能力，又通过逻辑代码补全了对“数值边界”的精确控制。

### C. 配置驱动的 RAG 路由

为了解决“体重既要看数值，又要看趋势”的复杂业务需求，我们在 `config/metrics.ts` 中引入了 **RAG 路由策略**：

```typescript
weight: {
  // ...
  ragConfig: {
    category: 'weight_trend',  // 告诉 Agent：查体重时，去知识库查 'weight_trend' 分类
    useDiffValue: true         // 告诉 Agent：匹配时用 '变化值' 而不是 '绝对值'
  }
}
```

Agent 代码中**没有任何硬编码的 `if (key === 'weight')`**。它完全根据 Config 动态决定查询参数。这意味着未来新增指标只需修改配置，无需改动核心代码。

## 4. 语义化 UI 展示

前端组件 `AnalysisCard.tsx` 不仅仅是渲染数据，还包含了**语义逻辑**：

- **颜色语义**：体重涨了是🔴红色（警告），但肌肉涨了是🟢绿色（好事）。这通过读取 Config 中的 `type: 'min'` 来自动判断。
- **渐进式披露**：默认只显示核心数据和趋势，点击“专家建议”才展开 RAG 检索到的详细文案，保持界面清爽。

## 5. 总结

📝 这套架构是 **Edge AI (端侧智能)** 的进阶实践。我们不仅实现了 **无需后端** 的智能分析，更引入了 **LangChain** 生态和 **DDD (领域驱动设计)** 思想。

它成功地将 **“严谨的数学计算”**、**“灵活的向量检索”** 和 **“工程化的配置管理”** 融合在一起，打造了一个**可扩展、高精度、低延迟**的前端健康顾问。
