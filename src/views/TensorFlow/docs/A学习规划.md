## 一、为什么 LLM 不适合你的体重数据分析？

| 问题              | 原因                                              | 正确解法                                |
| ----------------- | ------------------------------------------------- | --------------------------------------- |
| **Token 限制**    | 无法输入完整 CSV 数据（如 365 行体重记录）        | 用 `danfo.js` 在浏览器内处理全量数据    |
| **数值分析弱**    | LLM 擅长“讲故事”，不擅长“算趋势”                  | 用移动平均、线性回归等传统时间序列方法  |
| **中文乱码/幻觉** | 开源小模型 tokenizer 对中文支持差，易编造统计结论 | 报告内容由确定性算法生成 + RAG 补充知识 |
| **结果不可控**    | 同一输入多次输出不同                              | 使用确定性 ML 模型（如 TF.js 的 MLP）   |

> ✅ **结论**：**别用 LLM 做数值分析！用 JS 生态的 ML 工具链更稳、更快、更可控。**

## 二、🔧 三大技术精准补位：让传统 ML 更智能

| 技术      | 作用           | 适用阶段            | 示例                                       |
| --------- | -------------- | ------------------- | ------------------------------------------ |
| **RAG**   | 补“知识深度”   | 第3周起             | “7日均线下降0.7kg” → 自动检索健康减重建议  |
| **Agent** | 补“流程自动化” | 第3周起             | 用户上传 CSV → 自动清洗 → 预测 → 生成报告  |
| **微调**  | 补“预测精度”   | 第2周起（简单场景） | 用个人体重数据微调模型，识别“周末反弹”规律 |

> ⚠️ **优先级建议**：  
> **基础工具（TF.js + danfo.js） → Agent（提效） → RAG（增值） → 微调（进阶）**  
> _原因：Agent 和 RAG 几乎无需训练数据，1 天就能集成；微调需标注数据，适合有基础后尝试_

## 五、你的专属解决方案：“体重分析小工具 🛠️ ”详解

### 1. 数据处理（danfo.js）

```js
import * as dfd from "danfojs";

const df = new dfd.DataFrame({
  date: ["2025-01-01", "2025-01-02", ...],
  weight: [70.2, 70.0, ...]
});

// 计算7日移动平均
df["ma7"] = df["weight"].rolling({ window: 7 }).mean();
```

### 2. 可视化（Chart.js）

- 折线图：原始体重 vs 7日均线
- 标注异常点（如突增 >1kg）

### 3. 报告生成（确定性 + RAG）

> **确定性部分**（算法生成）：
> “本周体重下降 0.5kg，7日均线从 70.5 → 69.8。”

> **RAG 补充**（知识库检索）：
> “健康减重速度为每周 0.5–1kg。建议增加蛋白质摄入（如鸡蛋、鸡胸肉），并保证睡眠。”

### 4. 微调预测模型（TF.js MLP）

- 输入：过去 14 天体重
- 输出：未来 7 天预测
- 用历史数据微调，捕捉个人周期（如“周末吃多”）
